# 计划 · 检出远程分支

- **来源**：`docs/requirements.md` §3.6 第 1 行、FR-4.5（该文件已于 2026-09-13 删除，标签为历史出处）；`docs/plan.md` §10.3 第 1 行、D43
- **对应 TODO**：[TODO.md](../TODO.md) A-1
- **状态**：未排期（前置条件已满足，见下）

## 目标

把分支选择器里的**只读**远程分支列表变成动作：从一个 `origin/xxx` 检出本地分支。
三条路各自成立：

1. **没有同名本地分支** → `git switch -c <name> --track <remote>/<name>`
2. **能快进** → 快进
3. **分叉** → 让用户选：
   - **Rebase onto origin**：本地提交重放到远程之上
   - **Drop local commits**：`reset --hard` 到远程

## 现状

- 只读列表已交付（D43）：`remoteBranches` 读方法 + `GET /git-panel/remoteBranches`
  （`for-each-ref refs/remotes`），UI 区里的行**不是按钮、没有任何点击行为**，
  空时一句「没有远程分支（先获取一次）」。
- D43 当初收窄为「先只读，等冲突处理做完再弄」——理由是 rebase 与 drop 都可能进入冲突态，
  先有冲突 UI 才能安全收尾。**该前置已具备**：FR-9 的冲突分组与
  `RepoStatus.operation` 在途操作条（继续 / 跳过 / 中止）随 M4 与顺序 9 交付。

## 做法（按 D43 / §10.3）

- 判定顺序按上面三条；「能快进」用当前分支与 `origin/<name>` 的祖先关系现问仓库
  （与 `undoCommit` 判断推送状态同一基准：`merge-base --is-ancestor`）。
- **Drop local commits 破坏性**，必须走 `ui/armed.ts` 的「点击武装 → 3s 内再点」，
  确认文案点名「本地提交会被丢弃（不可恢复）」；执行前后端重核 HEAD。
- 落入冲突态时交给既有的在途操作条，不新造一套中止机制。

## 排期前要先定（文档点名）

1. **本地有未提交改动时怎么办**（拒绝？先贮藏？复用 FR-4.4 的「贮藏后切换」？）
2. **去掉 `<remote>/` 前缀后的重名规则**（远程名本身可能含 `/`，D43 已说明不拆 remote）

## 验收

真仓库集成测试覆盖三条路，以及分叉时的两种选择各自的结果与拒绝路径；
破坏性那一条断言武装确认与审计；冲突态能由在途操作条继续 / 中止。
