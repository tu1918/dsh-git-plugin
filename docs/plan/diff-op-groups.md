# 计划 · diff 视图的操作分区

- **来源**：`docs/plan.md` §10.3「diff 视图的操作分区」（产品方 2026-09-13 提出）
- **对应 TODO**：[TODO.md](../TODO.md) A-9
- **状态**：未排期；建议这一条**先做**，A-10 / A-11 / A-12 都挂在它划出的落点上

> 这四条只登记在 `docs/plan.md` §10.3：`docs/requirements.md` 是只读的（权限 `400`），
> 写不进 §3.6。

## 目标

把 diff 视图的操作按**视图操作 / 行间操作 / 行操作**三类分开，并给三类各留出位置，
让以后新增操作有明确落点，而不是继续往头部平铺。

## 现状

- 头部是一列平铺：路径 + 增删统计 + `spacer` + 布局段控（两枚）+ 刷新，
  见 `src/client/ui/DiffView.tsx:433-474`；头部本身是 sticky 的一条（`styles.ts:2166`）。
- diff **行内没有任何操作**：`DiffHunks` / `SplitHunks` 只画行（`DiffView.tsx:332`、`:289`）。
- **两处 hunk 之间现在什么都不渲染**：`DiffHunks` 把 hunk 首尾相接，中间没有行。

## 三类的落点

| 类别 | 指什么 | 落在哪 | 今天有什么 |
|---|---|---|---|
| 视图操作 | 改「怎么看」的 | 头部右侧的按钮区（现有段控与刷新所在） | 布局段控（A-10 会合成一枚）、刷新；A-11 加自动换行 |
| 行间操作 | 插在两行之间的动作 | **两处 hunk 之间的那一行** | 空。这一行要先由 A-12 渲染出来 |
| 行操作 | 针对某一行的动作 | 每一行尾部（`LineCell` 的 `diffCell` / 内联的 `diffLine`） | 空，一条都没有 |

三者在 DOM 上不可能同处一地，所以「分类」不是一根工具栏，而是**三个锚点**。

## 做法

1. **头部**：不写可见的分组文案（侧栏窄，属已知约束），用 `role="group"` +
   `aria-label`（新增 `diff.groupView` / `diff.groupGap` / `diff.groupLine` 一类 key）
   表达分类，视觉上只靠间距与一条分隔线区分。`diffSeg`（`styles.ts:2223`）这套托盘样式
   可以留给视图操作区的按钮组继续用，也可以随 A-10 退休——排期时一并定。
2. **行操作区只留槽位，不渲染空节点**：今天没有任何行操作，渲染一个空的可点区域比不渲染更糟
   ——与 D43①「只读行不用 `<button>`」是同一条判断。留位靠 CSS/结构约定（一个固定宽度的
   行尾槽），并在 `styles.ts` 的模块注释里写明它是留给谁的。
3. **行间区的实际内容由 A-12 填**：本条目只负责定下「gap 行就是行间操作的载体」，
   不提前造一个空行。

## 注意

- 三个锚点里只有视图操作区是「一直可见」的；gap 行只在有缝隙时出现，行操作槽只在有行操作时才有意义。
- 一旦出现真正的行操作（例如「复制该行」「以该行为锚点开注释」），它必须落在行尾槽，
  不要再回到头部——否则这次分区就白做了。

## 验收

三类各有一个可指认的落点（头部 group / gap 行 / 行尾槽位）；随便挑一个新增操作，
都能说出它属于哪一类、落在哪里；测试能按 `data-op-group` 之类稳定的锚点断言分区存在。
