# 计划 · 上游被远端删除时的提前报告

- **来源**：`docs/plan.md` D42 末段 ⚠、D45
- **对应 TODO**：[TODO.md](../TODO.md) C-2
- **状态**：未排期

## 背景

- 「获取所有远程」**有意不带 `--prune`**（D42）：prune 会删掉远端已不存在的远程跟踪 ref，
  那不是「按一下获取」隐含同意的动作。
- 代价（D42 末段已兑现）：远端删掉一条被跟踪的分支后，**过期的 `origin/<x>` 让
  `%(upstream:track)` 为空（不是 `[gone]`）**，于是 `upstreamGone` 保持为假、
  分支行不显示「上游已删除」，`pull` 要按下去才报错（D45 只把那次失败说清楚了）。

## 目标

在**不改写任何 ref** 的前提下，提前发现并报告「这条分支跟踪的上游在远端已不存在」。

## 做法（按 D42）

需要一次 `--prune` 或 **`git remote prune --dry-run` 的只读报告**：

- 倾向 **`remote prune --dry-run`**：它只列会被清理的 ref、不删任何东西，与「不 prune」的
  立场一致；把它作为获取之后的一次附带读取（或分支行的一个提示），失败只丢报告不丢主流程。
- 由此得到的集合用于：分支行显示「上游已删除」、必要时禁用/引导 `pull`。
- D45 已有的 `upstream-gone` 错误分类保留——它仍然是「用户已经按了 pull」时的正确出口。

## 注意

- 与 D45「不 prune 就无法区分上游被删与健在」是同一件事的两面：本项只是补上**只读的区分手段**，
  **不改变**「不自动清理」的决定。
- 多远程（`--all`）时报告要按远程分别给，别把 `origin` 的结论套到别的远程上。

## 验收

真仓库里删掉远端分支后，无需 pull 就能在面板上看到「上游已删除」；确认没有任何 ref 被删。
